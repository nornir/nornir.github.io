Accounts and tokens

Everything you have to request, buy, or generate before the stacks run. Viking’s own list, with the per-service key names, is Viking accounts and tokens. Secrets go only in Run/_host/secrets/secrets.env, Run/<stack>/secrets/, or Run/nornir-net-mounts/secrets/ on the host that needs them (Host layout). Never commit them, paste them in tickets, or put them in host.env or <stack>.run.env.

Generated secrets

These are random values you create, not accounts. stack.ps1 secrets new <stack> [KEY ...] writes a 32-byte URL-safe random value for the stack’s registry-listed *_SECRET, *_TOKEN and *_PASSWORD keys, for any key still holding a REPLACE_WITH_GENERATED... placeholder, and for any key you name. It replaces the placeholder where it is (secrets/secrets.env, else <stack>.run.env) or appends to secrets/secrets.env. Keys that already have a value are kept, so it is safe to re-run; stack.ps1 doctor treats REPLACE_ME / REPLACE_WITH_... values as empty. *_PASSWORD values get an Aa1! prefix to satisfy SQL Server complexity rules. SQL_SERVER_PASSWORD and connection strings are never generated (they belong to existing SQL logins). Empty optional client secrets are left alone, because empty means that client is disabled: name the ones you want, for example stack.ps1 secrets new viking-identity CORRECTION_SERVICE_CLIENT_SECRET.
