Migrating from the old layout

The old D:\Docker tree grew one convention per service (Builds\IdentityServer\.env.All*, mounted-configs\..., Run\segmentation-server, Nginx Proxy Manager). The stack layout gives every stack the same shape (Host layout). Moving over is a copy, not a rename: old files stay where they are until you delete them.

Copy files with Move-DockerHostLayout.ps1

Always run with -WhatIf first; it prints the old-to-new table without copying:

.\nornir-docker\deploy\Move-DockerHostLayout.ps1 -WhatIf
.\nornir-docker\deploy\Move-DockerHostLayout.ps1
.\nornir-docker\deploy\Move-DockerHostLayout.ps1 -From D:\Docker -To \\newserver\c$\srv\docker

It never deletes or overwrites. Env files that map to one <stack>.run.env are concatenated with a header naming each source; when a destination already exists it writes <dest>.migrated next to it for you to diff and merge. Old mounted-configs\nornir-build-* sessions are left alone unless you pass -IncludeWork. Then:

  1. Initialize-DockerHost.ps1 -Role <role> (creates the rest of the tree and the forwarding launchers);

  2. compare each migrated env file with its example.<stack>.run.env and rename keys (the script does not rename variables);

  3. stack.ps1 doctor;

  4. on the dev box, stop the old all-in-one viking compose project before the first stack.ps1 ... up (docker compose -p viking down); its published ports clash with the new stacks;

  5. delete the old files once the stacks run.

Behaviour changes worth knowing

  • Launchers under Builds\nornir-build used to be copies and broke after git pull; they are now forwarding launchers.

  • nornir-build joins nornir-dashboard_default automatically and publishes to mosquitto (the old default network name did not match the compose project).

  • nornir-build passes --shm-size=64g by default.

  • The TEM scripts choose NumPy automatically when no GPU is present.

  • compose.cursor-dev.yaml loads nornir-docker/.env with env_file, so settings such as NORNIR_SYNC_REMOTE reach the container without editing the compose file.
