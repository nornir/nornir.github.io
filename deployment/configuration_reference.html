Configuration reference

Every key in the committed templates, plus the run-time variables the nornir-docker launchers read. Templates are in nornir-docker/deploy/examples/ unless a path is given. Viking service keys (SQL connection strings, identity clients, segmentation models) are in the Viking deploy/examples/ templates and the Viking deployment docs (proxy, TLS, identity, segmentation).

“Required” means stack.ps1 (or the launcher) stops without it. Blank defaults mean unset.

Naming rules

Pattern

Meaning

NORNIR_*

Nornir behaviour (build, dashboard, MQTT, mounts).

NORNIR_DOCKER_*

Machine-level Docker settings for this host (layout root, host stacks, docker run limits).

VIKING_*

Viking deployment settings (domain, host names, repository path).

TLS_*

The shared certificate.

*_HOST suffix

A host filesystem path used as a bind source (NORNIR_REPO_ROOT_HOST, NORNIR_TESTDATA_HOST).

*_HOSTNAME / VIKING_HOSTNAME_*

A DNS name.

Stack keys

kebab-case; the same string is the registry key, the Run/<stack>/ folder, the <stack>.run.env file name, and the compose project name.

Run/_host/host.env

Template example.host.env. Machine settings for every stack on the host; no secrets.

Key

Default

Required

Consumer / meaning

NORNIR_DOCKER_USER_ROOT

D:\Docker / /srv/docker

yes

Layout root (Host layout). Filled in by Initialize-DockerHost.ps1. Also read from the process environment by every launcher.

NORNIR_REPO_ROOT_HOST

checkout containing stack.ps1

yes

nornir checkout on this host; forwarding launchers and -Sync use it.

VIKING_REPO_ROOT_HOST

Viking hosts

Viking checkout; without it the Viking registry is not loaded.

NORNIR_DOCKER_HOST_STACKS

role preset

yes

Comma list of stacks this host runs (stack.ps1 all, doctor). Presets: compute nornir-build,nornir-dashboard,viking-segmentation; web viking-proxy,viking-certs,viking-identity,viking-annotation,viking-corrections; iis viking-iis; dev nornir-dashboard.

VIKING_DOMAIN

connectomes.pitt.edu

Viking hosts

Parent domain; every VIKING_HOSTNAME_* defaults to <sub>.$VIKING_DOMAIN.

VIKING_HOSTNAME_IDENTITY

identity.<domain>

Override for one service name. Same for _WEBSVC (websvc), _ANNOTATION (annotation), _CORRECTIONS (corrections), _SEGMENTATION (segmentation), _SEGMENTATIONDEMO (segmentationdemo), _SEG_V3 (segmentation-v3), _SEG_V4 (segmentation-v4), _SEG_SEM_V1 (segmentation-sem-v1), _GALLERY (gallery), _TEM_GALLERY (gallery-tem), _SEM_GALLERY (gallery-sem). Keep overrides single-label under the domain so one wildcard certificate still covers them.

VIKING_COMPUTE_HOST

web

LAN name or IP of compute; the proxy forwards the segmentation names to it (ports 40443-40447).

VIKING_IIS_HOST

web

LAN name or IP of iis; the proxy forwards websvc to it on 443.

VIKING_UPSTREAM_DEFAULT

the IIS host

host:port for TLS connections whose SNI name matches no service.

VIKING_HTTP_UPSTREAM_WEBSVC

host:port: pass plain-HTTP websvc traffic through on port 80 instead of redirecting it to https, so old Viking clients’ http:// WCF and tile requests keep working.

TLS_MODE

letsencrypt

Viking hosts

letsencrypt | acme-eab | manual; tells viking-certs what to renew.

TLS_EMAIL

letsencrypt, acme-eab

ACME account contact for expiry notices.

TLS_CERT_NAME

$VIKING_DOMAIN

Folder under Certs/; every TLS service loads /certs/<TLS_CERT_NAME>/.

TLS_HOSTNAMES

every VIKING_HOSTNAME_*

Comma list the certificate must cover (certs manual, certs status).

TLS_ACME_SERVER

acme-eab

ACME directory URL from Pitt IT. The EAB key id and HMAC key go in Run/viking-certs/secrets/secrets.env as TLS_EAB_KID and TLS_EAB_HMAC_KEY.

TLS_STAGING

0

1 uses the Let’s Encrypt staging endpoint (untrusted certificates; no rate limits).

TLS_PFX_PASSWORD

empty

Password for Certs/<name>/cert.pfx. Also accepted as -PfxPassword.

NORNIR_GHCR_OWNER

jamesra

GHCR namespace for docker-pull.ps1 / docker-push.ps1 (ghcr.io/<owner>/nornir:*).

Run/_host/secrets/secrets.env

Template example.host.secrets.env. Mode 600 on Linux.

Key

Default

Required

Consumer / meaning

GITHUB_TOKEN

GitHub fine-grained PAT (Accounts and tokens). The launchers never load it into the host process; it reaches containers only through --env-file. Also run docker login ghcr.io once per host.

Run/_host/targets.psd1

Template example.targets.psd1; a PowerShell data file, one entry per target under Targets.

Field

Meaning

Ssh

user@host or a Host alias from ~/.ssh/config. Must log in without a password prompt.

SshOptions

Extra ssh/scp arguments, for example @('-p', '2222') or @('-J', 'jump.example.edu').

Os

linux or windows (Windows targets need pwsh as the OpenSSH default shell).

Root

That host’s NORNIR_DOCKER_USER_ROOT.

Stacks

Stacks all means for this target (informational for -Images load; the target’s own NORNIR_DOCKER_HOST_STACKS decides what all runs there).

Repos

@{ NORNIR_REPO_ROOT_HOST = '<path>'; VIKING_REPO_ROOT_HOST = '<path>' }: checkouts that -Sync fast-forwards.

Tunnels

ssh -L specs (local:host:port) opened by stack.ps1 tunnel.

CertPush

$true: stack.ps1 certs push (usually -From web) without -Target copies the certificate here.

Viking keys that stack.ps1 checks

The Viking registry marks these as required; set them in the Viking stack’s run env (templates in <Viking>/deploy/examples/):

  • viking-proxy: VIKING_DOMAIN, VIKING_COMPUTE_HOST, VIKING_IIS_HOST (in host.env on web, above).

  • viking-certs: VIKING_DOMAIN, TLS_MODE, TLS_CERT_NAME.

  • viking-identity: SQL_SERVER_HOST, SQL_SERVER_USER, SQL_SERVER_PASSWORD, SQL_SERVER_IDENTITY_DB, SQL_SERVER_CONFIG_DB, SQL_SERVER_GRANTS_DB, IDENTITY_SERVER_SECRET, IDENTITY_SERVER_API_SECRET, IDENTITY_SERVER_MVC_SECRET, IDENTITY_SERVER_RO_VIKING_SECRET; secret files secrets.json, Duende_License.key.

  • viking-annotation: ConnectionStrings__AnnotationConnection, IdentityServer__Endpoint, IdentityServer__ClientId, IdentityServer__ClientSecret.

  • viking-corrections: IdentityServer__Endpoint, IdentityServer__ClientSecret, CorrectionService__Name.

  • viking-iis: VIKING_IIS_DEPLOY_ROOT.
